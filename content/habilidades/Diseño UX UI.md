
**UX (User Experience)** se centra en cómo se siente y funciona un producto para el usuario.  
**UI (User Interface)** se centra en cómo se ve y se interactúa visualmente con ese producto.  

Aunque son disciplinas distintas, en la práctica suelen trabajar juntas y muchas veces las ejerce la misma persona (especialmente en startups y equipos pequeños).

---

### 1. Diferencia entre UX y UI

| Aspecto                        | UX (User Experience)                  | UI (User Interface)                  |
|--------------------------------|---------------------------------------|--------------------------------------|
| **Enfoque**                    | Experiencia completa del usuario      | Apariencia e interacción visual      |
| **Pregunta principal**         | ¿Es útil, usable y valioso?           | ¿Se ve claro, atractivo y consistente? |
| **Entregables típicos**        | Research, flujos, wireframes, tests   | Interfaces, componentes, prototipos visuales |
| **Habilidades clave**          | Investigación, arquitectura, usabilidad | Diseño visual, tipografía, color, interacción |
| **Objetivo**                   | Resolver problemas del usuario        | Facilitar y hacer agradable la interacción |

---

### 2. Proceso completo de Diseño UX/UI

| Fase                           | Qué se hace                           | Entregables comunes |
|--------------------------------|---------------------------------------|---------------------|
| **1. Research / Descubrimiento**| Entender usuarios, problema y contexto | Entrevistas, surveys, benchmark, data |
| **2. Definición**              | Sintetizar hallazgos y definir el problema | Personas, jobs-to-be-done, problem statement |
| **3. Ideación**                | Generar posibles soluciones           | User flows, sketching, brainstorming |
| **4. Estructura**              | Organizar la información y navegación | Information Architecture, sitemaps, user flows |
| **5. Wireframing**             | Diseñar la estructura sin detalle visual | Low-fidelity wireframes |
| **6. UI Design**               | Aplicar estilo visual y componentes   | High-fidelity mockups, design system |
| **7. Prototipado**             | Hacer la interfaz interactiva         | Prototipos clicables |
| **8. Testing**                 | Validar con usuarios reales           | Usability tests, feedback, iteraciones |
| **9. Handoff y colaboración**  | Preparar todo para desarrollo         | Specs, assets, documentación |
| **10. Iteración post-lanzamiento** | Mejorar con datos reales           | Análisis de comportamiento + rediseños |

| **Accessibility (a11y)**       | Diseño inclusivo                      | Cada vez más alta |

### 4. Principios fundamentales de UX

| Principio                      | Qué significa |
|--------------------------------|---------------|
| **Usabilidad**                 | Que sea fácil de usar |
| **Utilidad**                   | Que resuelva un problema real |
| **Deseabilidad**               | Que genere atracción y conexión emocional |
| **Accesibilidad**              | Que pueda usarlo la mayor cantidad de personas posible |
| **Findability**                | Que la información se encuentre fácilmente |
| **Credibilidad**               | Que transmita confianza |
| **Valor**                      | Que el usuario perciba beneficio claro |
| **Consistencia**               | Que se comporte de forma predecible |
| **Feedback**                   | Que el sistema responda a las acciones del usuario |
| **Control y libertad**         | Que el usuario pueda deshacer y navegar sin sentirse atrapado |
| **Prevención de errores**      | Diseñar para evitar fallos |
| **Jerarquía y claridad**       | Guiar la atención hacia lo importante |

---

### 5. Principios fundamentales de UI

| Principio                      | Qué implica |
|--------------------------------|-------------|
| **Jerarquía visual**           | Organizar elementos por importancia |
| **Contraste**                  | Hacer que lo importante destaque |
| **Alineación**                 | Orden y estructura visual |
| **Proximidad**                 | Agrupar elementos relacionados |
| **Espaciado (White space)**    | Dar respiración y claridad |
| **Tipografía**                 | Legibilidad, escala y personalidad |
| **Color**                      | Significado, accesibilidad y marca |
| **Consistencia visual**        | Mismos patrones en todo el producto |
| **Affordances**                | Que se entienda cómo interactuar |
| **Feedback visual**            | Estados (hover, active, loading, error…) |
| **Simplicidad**                | Eliminar lo innecesario |
| **Diseño responsive**          | Adaptación a diferentes tamaños de pantalla |

### 7. Entregables más comunes

| Entregable                     | Fase típica | Para qué sirve |
|---------------------------------|-------------|----------------|
| **User Personas**               | Research    | Representar a los usuarios |
| **Journey Maps**                | Research / Definición | Entender la experiencia completa |
| **Empathy Maps**                | Research    | Profundizar en motivaciones |
| **User Flows**                  | Ideación / Estructura | Mapear caminos del usuario |
| **Sitemaps**                    | Estructura  | Organización de contenidos |
| **Wireframes**                  | Diseño temprano | Estructura sin distracción visual |
| **Mockups de alta fidelidad**   | UI Design   | Diseño visual final |
| **Prototipos interactivos**     | Testing     | Simular la experiencia |
| **Design System / UI Kit**      | Escalado    | Consistencia y velocidad |
| **Usability Test Reports**      | Validación  | Hallazgos y recomendaciones |
| **Especificaciones / Dev handoff** | Entrega | Facilitar la implementación |

---

### 8. Habilidades complementarias de alto valor

- Pensamiento analítico y de negocio
- Comunicación y presentación de decisiones de diseño
- Colaboración con Product Managers y Developers
- Escritura (UX Writing)
- Nociones de frontend (HTML/CSS/React) para mejor handoff
- Análisis de datos de producto (Mixpanel, Amplitude, Hotjar…)
- Facilitación de workshops
- Criterio estético + criterio de usabilidad
- Empatía real con el usuario
- Capacidad de priorizar (no todo se puede diseñar perfecto)

### 9. Niveles de dominio en UX/UI

| Nivel                          | Capacidad principal                        | Resultado típico |
|--------------------------------|--------------------------------------------|------------------|
| **Junior**                     | Ejecuta diseños con supervisión            | Pantallas y componentes |
| **Mid-Level**                  | Lleva features completas                   | Flujos y soluciones autónomas |
| **Senior**                     | Define problemas y soluciones complejas    | Impacto en el producto |
| **Lead / Principal**           | Define dirección de diseño y sistemas      | Consistencia y visión |
| **Product Designer**           | Une UX + UI + negocio + datos              | Decisiones de producto |
| **Head of Design / Design Manager** | Lidera equipo y cultura de diseño     | Escalado del diseño en la organización |

### 10. Errores comunes en UX/UI

- Diseñar sin investigar
- Enamorarse de la solución antes de entender el problema
- Ignorar la accesibilidad
- Crear interfaces bonitas pero difíciles de usar
- No testear con usuarios reales
- Falta de consistencia visual y de interacción
- Sobre-diseñar (añadir complejidad innecesaria)
- No documentar decisiones ni componentes
- Trabajar desconectado de negocio y de datos
- Entregar diseños imposibles o poco realistas de implementar
